# Handoff: Конструктор печати + Оформление заказа

## Overview
Онлайн-конструктор печати для ИП/ООО («Лаборатория печатей», Оренбург). Два экрана одного потока:
1. **Конструктор (build)** — выбор типа печати, ввод реквизитов по ИНН с автоподстановкой из реестра ФНС, живое превью оттиска с выбором макета, выбор оснастки, срочность, итоговая стоимость.
2. **Оформление заказа (checkout)** — способ получения (Самовывоз / Курьер / Почта·СДЭК), оплата, сводка заказа, финальная кнопка.

Переход build → checkout по кнопке «Оформить заказ»; назад — «Вернуться к конструктору». Состояние конструктора при переходе сохраняется.

## Состав пакета
- `Главная.dc.html` — главная страница сайта.
- `Конструктор.dc.html` — конструктор печати (выбор ситуации / вход в поток).
- `Конструктор - реквизиты.dc.html` — конструктор + оформление заказа (desktop), описан ниже.
- `Конструктор - реквизиты (моб).dc.html` — мобильная версия того же потока.
- `Адаптив.dc.html` — адаптивные раскладки (планшет / мобайл).
- `Админка справочников.dc.html` — внутренняя админка: справочники (master-detail).
- `Услуга - Факсимиле / Электронная подпись / Полиграфия / Отрисовка по фото / Лазер.dc.html` — страницы услуг (ссылки из блока «И ещё мы умеем» на Главной). Общий шаблон: вкладки услуг → hero с фактами и местом под фото → прайс «Что можно заказать» → «Как работаем» (4 шага) → требования + FAQ-аккордеон → форма заявки (имя, телефон, файл; состояние «Заявка принята») → «Другие услуги». Контент каждой услуги — объект в `data()` логики; на бэкенде это одна шаблонная страница с разными данными.
- `reference/` — ранние варианты конструктора, только для контекста.
- `screenshots/` — скриншоты экранов.

Подробная спецификация ниже покрывает конструктор и оформление; остальные страницы — воспроизводить по файлам.

## About the Design Files
Файлы в этом пакете — **дизайн-референсы в HTML**: прототипы, показывающие внешний вид и поведение, а не продакшн-код. Задача — **воссоздать их в окружении целевого проекта** (React/Vue/и т.п.) с его паттернами и библиотеками; если окружения нет — выбрать подходящий фреймворк. Данные (ИНН, реестр, ПВЗ, цены) замоканы.

Файлы `.dc.html` открываются в браузере напрямую (рядом `support.js` и `_ds/`). Разметка — в `<x-dc>`, логика — в `<script data-dc-script>` (класс `Component`, метод `renderVals()` отдаёт значения для шаблона `{{ … }}`; `<sc-if>` = условный рендер, `<sc-for>` = список).

## Interactions & Behavior
- **ИНН**: только цифры, до 12. При длине ≥10 → `searching`, debounce/запрос (мок 850 мс). Успех → `found`, заполняются org/city/ogrn (ОГРНИП для 12 цифр, ОГРН для 10). Мок: `5610100200` → `notfound` + ручной ввод. Менее 10 цифр → `idle`.
- **Реальная интеграция**: поиск по ИНН — DaData / API ФНС (ЕГРЮЛ/ЕГРИП).
- Превью оттиска перерисовывается на лету из org/city/inn и выбранного макета.
- Смена типа печати сбрасывает выпадашку; «копия» включает `ownLayout`.
- Цены пересчитываются мгновенно; префикс «от » при своём макете/копии.
- Checkout: выбор плиток мгновенный, без анимации высоты; блок «Способ получения» тянется, «Оплата» прижата вниз.
- **ПВЗ**: в прототипе кнопка циклически перебирает 3 мок-адреса. **В проде — модальное окно выбора ПВЗ** (карта + список; `.dialog-backdrop` + `.dialog` из Nocturne) по выбранной службе (СДЭК / Boxberry / DPD, их виджеты/API). Не реализовано в дизайне.
- Hover кнопок/плиток — accent-рамка/тинт; focus — `:focus-visible { outline:2px solid var(--color-accent); outline-offset:2px }`; disabled — opacity .45 (из `.btn`/`.input`).
- **Валидация (к реализации)**: «Оформить заказ» на checkout неактивна, пока: реквизиты не заполнены (build), для Курьера пуст адрес, для Почты/СДЭК не выбран ПВЗ. Телефон/email для чека в макете пока не предусмотрены — согласовать.
